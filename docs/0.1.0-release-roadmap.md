Probably not the major decisions. Profiling may explain why they occur and might expose optimization opportunities, but the selector should follow measured latency outcomes.

Do not autotune during installation

Use an explicit command:

fortran-nlp-calibrate


Possible alternatives:

python -m fortran_nlp.calibrate


Installation-time calibration is a bad default because installation might occur:

inside CI;
during a Docker image build;
on a different machine from deployment;
under heavy background load;
inside a restricted VM;
on a shared server;
before the final CPU allocation is known.

Empirical installation/runtime tuning is established in systems such as ATLAS, while nearest-neighbor libraries such as FLANN also use automatic algorithm configuration. The important product decision here is making calibration explicit, reproducible, and optional rather than surprising users during installation.

1. Explicit user choice
2. Compatible calibrated machine profile
3. Shipped benchmark-informed fallback policy
